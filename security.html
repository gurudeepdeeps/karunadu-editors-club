Security Policy

🔒 Scope: Website Code & Community Safety • Responsible Disclosure

Security Objective: We prioritize visitor safety by maintaining clean static code, enforcing safe external link rel attributes, and maintaining a direct channel to report security issues or malicious links.

1. Client-Side Security Standards

The code in this repository adheres to established client-side security practices:

  • External Link Isolation: All external links to third-party domains use rel="noopener noreferrer" to prevent reverse-tabnabbing and protect window context.
  • No Dynamic Code Execution: Our JavaScript does not invoke eval(), Function() constructors, or unsafe script injections.
  • No Sensitive Credentials: No API secret tokens, database credentials, or server private keys exist on this client codebase.

2. Reporting Security Issues (Responsible Disclosure)

If you identify a security issue, vulnerability, or a compromised external link on this website, we welcome your responsible disclosure:

  • GitHub Security Advisory / Issue: Open a report or security advisory on our public GitHub repository.
  • Community Security Contact: Contact moderators in our Community Chat room.

Please include a detailed description of the potential vulnerability, affected URLs, and reproduction steps so we can investigate and address it promptly.

3. Safe Download Recommendations for Users

Because external tools and creative assets are shared by the community across external Google Drive links, we always recommend visitors:

  • Run active local antivirus or Windows Defender / macOS Gatekeeper scans on all downloaded archives.
  • Verify archive checksums or digital signatures where available.
  • Never install software from unverified or suspicious external re-upload links.
